# 测试点内容「清空」语义：PATCH 空字符串 = 显式置空

- 日期：2026-08-26
- 状态：已实施

## 背景

2026-08-25 的增量更新协议（`2026-08-25-test-case-incremental-update.md`）把 upserts 中
`input / expected_output` 的「留空」定义为「内容不变」。前端编辑器按行 diff 提交完整内容，
用户在编辑器中把某一侧文本框清空后保存，提交的是 `{ id, input: "", ... }`——后端按
「内容不变」忽略该字段，旧 MinIO 对象引用原样保留，表现为「输入删不掉」。

## 决策

细化 PATCH 增量语义（修正而非推翻原决策意图：部分更新仍然可用）：

| upserts 带 id 时 | 语义 |
| --- | --- |
| `input / expected_output` 缺省或为 null | 内容不变（仅改名 / 调序场景不受影响） |
| 传字符串（含空串） | 整体替换该侧内容；空字符串 = 显式清空 |

- 「清空」实现为**上传空对象**（`put_bytes(key, b"")`），`input_oss_id /
  expected_output_oss_id` 保持非空：「test_cases 表内全部为正式测试点」约定与表结构
  不变，无需迁移；判题自然读入空 stdin / 与空期望输出比对（无 stdin 题目是合法形态）
- 已有行两侧同时显式置空 → 1001（与新增路径「输入输出不能全空」一致）；删除测试点走 delete_ids
- 全量 PUT（`PUT /problems/{id}/test-cases`）语义不变

## 后果

- 正向：编辑器清空某侧内容可正确生效并回读为空；无需 NULL 语义与库结构变更；
  测试点不会因单侧被清空而掉出「正式测试点」集合（发布门禁 / 判题可见性不受扰动）
- 负向：API 客户端若此前依赖「传空串 = 不变」，行为改变（当前唯一调用方为前端编辑器，
  其始终提交完整内容，不受影响）
- 中立：URL、表结构、gRPC 协议不变
