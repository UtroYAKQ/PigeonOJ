# 接口权限列直接标注角色 code

- 日期：2026-08-15
- 状态：已采纳

## 背景

详细设计第 4 节的接口表中需要表达每个端点的权限要求。候选方案有 A（权限点编码 / 权限组）与 B（直接标注角色 code）两种表达方式。

## 决策

接口表的「权限」列直接标注角色 code（逗号分隔），如 `admin/tutor/team_creator/team_admin`；`public` = 无需登录，`auth` = 登录即可，`owner` = 资源所有者本人（或团队内对应角色）。

- 判定在应用层按角色分支（配套决策：`2026-08-15-rbac-simplification.md`）
- `team_*` 角色仅在团队资源上下文（`scope='team'`、`object_id=<team_id>`）叠加判定

## 原因

- 角色集合固定（6 个），角色 code 可直接传达语义，无需额外映射层
- 团队角色的「叠加」语义（全局角色 + 团队角色）用 code 标注最直观
- 与「功能权限不落表」的简化一致，避免引入第二套编码体系

## 替代方案

- **权限点编码 / 权限组（如 `problem:manage`）**：被否决——需要维护编码与角色之间的映射，而当前矩阵稳定、角色少，映射是纯开销

## 影响

- 所有契约文件（`docs/contracts/*.md`）的端点表统一用角色 code 标注权限
- 新增端点时直接列允许的角色 code；`admin` 隐含全部能力
- 权限矩阵（`docs/architecture.md`）与接口权限列保持一致，作为矩阵的唯一入口
