# 安全与权限

> 跨模块的安全规则与 RBAC 权限设计。AI 写代码或改接口前读本文件。

## 角色与作用域

| 作用域 | 角色 code | 说明 |
| --- | --- | --- |
| global | `admin` | 系统管理员 |
| global | `tutor` | 导师 |
| global | `user` | 普通用户（默认） |
| team | `team_creator` | 团队创建者 |
| team | `team_admin` | 团队管理员 |
| team | `team_member` | 团队成员 |

- 统一由 `roles`（静态种子）+ `user_roles`（运行时授权）承载；`scope` 标定全局/团队，`object_id` 标定生效对象
- 功能权限不落表，由中间件装载角色后按角色 `code` 在应用层分支判定
- `team_creator` 权限集 ⊇ `team_admin`（创建者额外含「分配管理员」）
- 团队角色仅在团队资源上下文（`scope='team'`、`object_id=<team_id>`）叠加判定
- 资源级可见性（题目 / 题单 / 比赛）由查询层按 `owner_id / team_id / visibility` 过滤

## 角色职责（种子）

| 角色 | 职责 |
| --- | --- |
| `admin` | 全部能力：用户管理、系统配置、运维、公开比赛、团队等 |
| `tutor` | 创建团队、创建公开比赛、管理题目 |
| `user` | 浏览题目 / 题单 / 比赛、提交（默认角色） |
| `team_creator` | 团队内全部管理：邀请 / 成员 / 题库 / 题单 / 比赛，含「分配管理员」 |
| `team_admin` | 同 `team_creator`，但不含「分配管理员」 |
| `team_member` | 查看团队题单 / 比赛、提交 |

## 越权规则

- 所有用户数据查询必须带 `WHERE user_id = ?`（当前登录用户）
- 团队资源查询必须带 `WHERE team_id = ?`（用户所在团队）
- 提交 `contest_id` 由服务端从请求上下文推导，不信任客户端传入
- `submit_type=verify` 须校验 `verification` 记录的 `verifier_id` 与当前用户一致
- 返回用户对象必须排除 `password` 字段

## 沙箱安全

- 代码执行仅在 nsjail 沙箱进行；限制 CPU / 内存 / 时间 / 进程 / 文件系统，限制输出大小、磁盘配额、CPU 核数
- 沙箱默认禁止网络访问（禁外网 / 禁内网元数据）
- 代码和测试点由判题节点从内部存储准备到本地临时目录；不提供用户可控 URL 执行接口，不接受内联测试点 payload
- **后端进程不执行任何用户代码**；经 gRPC 网关派发到判题节点执行，后端仅承担注册认证、负载均衡、结果落库

## 凭证与密钥

- 密码、会话 Token 哈希存储（bcrypt/argon2）
- 邮箱验证码、验题邀请链接存 Redis（短 TTL，不落库）
- 不硬编码密钥 / token / 密码 / URL；不在日志记录敏感信息
- 配置值（如 `*.password`）管理接口一律掩码返回，提交掩码值视为未修改

## 上传与文件安全

- 文件统一写入 MinIO；对象 key 由服务端生成（不信任客户端路径）
- 类型白名单，大小上限（头像 ≤2MB、测试点 ≤16MB、插图 ≤5MB）
- 判题测试点文件仅判题服务内部可读，不向前端暴露下载 / 预签名 URL

## 提交与频控

- 提交限频：按用户 + 题目提交冷却（Redis）+ 全局判题并发上限；提交代码大小上限 64KB（UTF-8 字节）
- 登录失败超次触发 `frozen`

## AI 安全

- AI 修改代码必须用户确认后应用，避免自动覆盖用户代码
- AI 能力暂缓实现，相关契约与依赖已摘除
